# UX 可测试性与测试策略（SOP）

> 本文件为计算器网站项目的 UX 测试策略标准作业流程，覆盖可测试性映射、不可自动化项、可访问性分层、核心交互流程与测试环境依赖。所有结论需与 `docs/design-system.md` 中的设计元素与组件状态保持一致。

---

## 1. 可测试性映射表

> 说明：测试层级中"组件测试"指 Vitest + Vue Test Utils / Testing Library 级别的 DOM 与交互单元测试；"Playwright"指 E2E 浏览器行为验证；"Vitest"指纯函数 / 工具函数单元测试；"人工验证"指必须由 QA 在真实环境（含真机）下手动执行的检查。

| 设计元素 | 状态 | 测试层级 | 归属理由 |
| --- | --- | --- | --- |
| 数值输入框 | 空（未填写） | 组件测试 + Playwright | 组件层验证 DOM 属性（`required`、`aria-invalid="false"`、`placeholder`）；Playwright 验证 Tab 进入后焦点环与提示文案可见 |
| 数值输入框 | 聚焦 | Playwright | 需在真实浏览器中验证 `:focus-visible` 样式与 IME 中文输入法合成事件不卡焦点 |
| 数值输入框 | 有效（通过校验） | 组件测试 | 校验函数与 `aria-invalid` 切换属于纯逻辑与 DOM 派生，无需真实浏览器 |
| 数值输入框 | 无效（校验失败） | 组件测试（DOM 属性 + 错误文案）+ Playwright（错误时聚焦） | 错误文案渲染属组件层；"出错后焦点跳到首个错误字段"是跨组件时序行为，需 E2E 验证 |
| 数值输入框 | 禁用（disabled） | 组件测试 | `disabled` 属性切换属组件层 props 控制 |
| 数值输入框 | 只读（readonly） | 组件测试 | `readonly` 属性切换属组件层 props 控制 |
| 计算按钮 | 初始（未达可计算条件） | 组件测试 | 由表单派生状态决定，组件层可断言 `disabled` |
| 计算按钮 | 禁用 | 组件测试（`disabled` 属性） | DOM 属性断言即可 |
| 计算按钮 | 可点击 | 组件测试 | `@click` 绑定与可点击态属组件层 |
| 计算按钮 | 计算中（loading） | 组件测试 + Playwright（点击触发计算） | loading 文案与禁用双重控制属组件层；"点击后是否真触发一次计算"属端到端行为 |
| 结果区 | 空状态（未计算） | 组件测试（DOM 文案） | 占位文案与无障碍属性属组件层 |
| 结果区 | 已计算 | 组件测试（DOM 文案）+ Playwright（修改输入触发待重算） | 文案与公式代入渲染属组件层；"修改输入后状态切换"是跨字段时序，需 E2E |
| 结果区 | 待重算（输入已变更） | 组件测试 + Playwright | `aria-disabled="true"` 与提示文案属组件层；触发时序属 E2E |
| 结果区 | 计算失败（异常） | 组件测试 | 错误边界兜底属组件层（全局 `errorHandler`） |
| 错误提示 | 行内（字段下方红字） | 组件测试（`aria-describedby` 关联） | `aria-describedby` 指向 ID 的关联属组件层可断言 |
| 错误提示 | 整页（不可恢复错误页） | 组件测试（`aria-describedby` 关联）+ Playwright（错误时焦点跳转） | 整页错误的可达性与焦点跳转属端到端行为 |
| 广告容器 | 未加载（脚本被拦截） | Playwright | "无广告时页面可用"必须验证 CLS、布局与核心交互链路，需 E2E |
| 广告容器 | 加载中 | Playwright | 加载占位与防 CLS 骨架需真实网络时序 |
| 广告容器 | 已填充 | 人工验证 | 真实素材尺寸、内容合规、品牌安全需人工复核 |
| 广告容器 | 加载失败 | Playwright | 失败兜底（折叠为空、不影响核心功能）需 E2E 验证 |
| 颜色对比度（全局） | — | 自动化工具 axe-core | 对比度比值计算是确定性规则，可由 axe-core 静态扫描完成 |
| 触控目标尺寸 | — | Playwright `boundingBox` 测量 ≥ 44×44 | 命中区域大小需真实布局渲染后才能测量 |
| 字体与断点变化 | — | Playwright 多视口截图对比 + 人工视觉确认 | 像素级差异需截图比对；最终视觉判定需 QA 主观评估 |

## 2. 不可自动化项清单

> 以下项必须由 QA 在真实环境（含真机）下人工验证，任何自动化方案均不能替代。

### 2.1 真机触控手感
- **验证步骤**：在每台真机上分别打开百分比计算器页面，依次执行：点击输入框唤起键盘 → 输入数字 → 点击计算按钮 → 长按结果区尝试选中 → 双指缩放页面。记录点击响应延迟、误触率、滑动页面是否触发键盘回缩。
- **所需工具/设备**：iPhone 13、iPhone SE（第 3 代）、Pixel 7、Samsung S22 共 4 台真机，iOS 16+ 与 Android 13+ 系统版本。
- **通过判定标准**：点击响应主观顺滑无明显卡顿；按钮按压态视觉反馈清晰；键盘弹出/收起不遮挡主按钮；横竖屏切换无内容丢失。

### 2.2 屏幕阅读器实际朗读效果
- **验证步骤**：使用 NVDA（Windows + Chrome）与 VoiceOver（iOS + Safari）分别走查百分比计算器完整流程（输入 → 校验失败 → 计算 → 修改输入 → 重置），记录朗读顺序、停顿、是否漏读关键信息。
- **所需工具/设备**：Windows 11 + NVDA 最新版、iOS 16+ + VoiceOver、对比耳机监听。
- **通过判定标准**：所有交互元素可被朗读且顺序符合视觉顺序；错误提示在出错时立即被朗读；结果区状态切换有明确宣告（"已计算"、"输入已变更，请重新计算"等）。

### 2.3 微信内置浏览器的 Web Share API 实际支持
- **验证步骤**：在 Android 微信、iOS 微信中分别打开页面，点击"分享结果"按钮，观察是否调起微信原生分享面板或降级到剪贴板方案。
- **所需工具/设备**：Android 微信 v8.0.40+、iOS 微信 v8.0.40+。
- **通过判定标准**：能调起微信分享面板为优；降级到"已复制链接 + 提示文案"亦视为通过；但必须保证点击后不出现白屏或 JS 报错。

### 2.4 iOS Safari 软键盘与吸底按钮
- **状态**：**已转为过期（DEPRECATED）**
- **说明**：原方案曾计划使用 `position: fixed; bottom: 0` 让计算按钮吸底以规避 iOS Safari 软键盘遮挡；经架构评审已裁决改回常规文档流布局。本项不再作为人工验证项，仅在此留痕以备审计追溯。

### 2.5 真实广告位加载后视觉一致性
- **验证步骤**：在开启广告拦截与关闭广告拦截两种场景下，分别截图首屏与计算完成态，对比广告容器占位、内容形态、与正文区视觉对齐情况；记录 CLS 数值。
- **所需工具/设备**：Chrome DevTools Performance 面板、Lighthouse、3 个不同广告商账号样本。
- **通过判定标准**：广告填充后不破坏既有网格；CLS < 0.1；广告与正文之间间距符合 design token；无广告素材遮挡关键操作按钮。

## 3. 可访问性测试分层

### 3.1 自动化可覆盖项

| 项 | 工具 | 通过条件 |
| --- | --- | --- |
| 颜色对比度 | axe-core | 所有正文文本对比度 ≥ 4.5:1，大字体 ≥ 3:1 |
| `label` 与控件关联 | axe-core | 每个可输入控件均有可见或 `aria-label`/`aria-labelledby` 关联 |
| `aria-invalid` 存在性 | axe-core | 校验失败时错误字段 `aria-invalid="true"` 且 `aria-describedby` 指向错误文案 |
| Tab 可达性 | Playwright | 所有可交互元素可经 Tab 顺序到达，焦点环可见，无键盘陷阱 |
| 触控目标尺寸 | Playwright `boundingBox` 测量 | 主操作按钮 ≥ 44×44px，输入框高度 ≥ 44px |

### 3.2 必须人工验证项

| 项 | 工具/方式 | 通过条件 |
| --- | --- | --- |
| 朗读顺序 | NVDA + VoiceOver 走查 | 朗读顺序与视觉顺序一致，无错序、无漏读 |
| 朗读内容可理解性 | QA 主观评估 | 错误提示、状态变化文案自然易懂，无机器翻译感 |
| 焦点管理 | 人工操作 + 屏幕阅读器监听 | 校验失败后焦点跳到首个错误字段；结果区状态切换不影响焦点位置 |
| 错误恢复体验 | 人工操作完整流程 | 用户从错误状态恢复到正常计算的路径清晰，无死路 |

### 3.3 关于 Lighthouse a11y 分数的声明

> **Lighthouse a11y 分数 ≠ WCAG 合规。**

Lighthouse a11y 分数作为**回归监控阈值**使用：CI 流水线中分数 **≥ 95** 时仅记录趋势，不视为合规结论；分数跌破阈值时发出告警但**不作为合规结论**，需由 QA 按本文件第 3.1、3.2 节逐项复核后给出最终合规判定。

## 4. 核心交互流程测试用例

> 共 5 条核心流程。每条含：流程编号 / 前置条件 / 操作步骤 / 断言点 / 测试层级。

### 流程 1：正常计算
- **前置条件**：浏览器打开百分比计算器页面。
- **操作步骤**：在 a 输入框输入 `200`，在 b 输入框输入 `15`，点击"计算"按钮。
- **断言点**：
  1. 主结果区显示 `30`；
  2. 公式代入过程正确展示（如 `200 × 15% = 30`）；
  3. "复制结果"按钮处于可用态（`aria-disabled="false"`）。
- **测试层级**：Playwright

### 流程 2：校验失败并聚焦
- **前置条件**：页面已打开，a 已输入合法值，b 留空。
- **操作步骤**：直接点击"计算"按钮。
- **断言点**：
  1. b 字段下方显示红字错误文案 `请填写{字段名}`；
  2. 焦点跳到 b 输入字段；
  3. a 字段已输入的值原样保留不被清空；
  4. 计算按钮处于置灰禁用态（`disabled="true"`）。
- **测试层级**：Playwright

### 流程 3：修改输入后待重算
- **前置条件**：已成功完成一次计算（结果区处于"已计算"态）。
- **操作步骤**：修改 a 输入框的值为 `250`（不点击计算按钮）。
- **断言点**：
  1. 结果区进入"待重算"态，显示提示文案 `输入已变更，请重新计算`；
  2. 旧的计算结果（`30`）仍保留在结果区；
  3. 结果区 `aria-disabled="true"`，表示当前结果已不再可信；
  4. "复制结果"按钮同步置灰。
- **测试层级**：组件测试 + Playwright

### 流程 4：重置清空
- **前置条件**：已成功完成一次计算。
- **操作步骤**：点击"重置"按钮。
- **断言点**：
  1. 结果区回到空状态占位文案；
  2. 输入框全部清空、错误提示全部消失；
  3. 计算按钮回到初始禁用态；
  4. GA4 事件字典中**不包含** `calculate` 事件（重置操作不发送新的计算事件）。
- **测试层级**：组件测试

### 流程 5：广告缺失降级
- **前置条件**：广告脚本被拦截（浏览器广告拦截插件或网络层屏蔽）。
- **操作步骤**：完整执行流程 1（输入 a=200, b=15 → 点击计算）。
- **断言点**：
  1. 计算结果、复制、分享功能全部可用；
  2. 页面布局无任何偏移（CLS = 0）；
  3. 广告容器折叠为空，不显示破图占位；
  4. 控制台无广告相关报错阻断主流程。
- **测试层级**：Playwright

## 5. 测试环境依赖与 BLOCKED 项

> 以下项因前置条件未到位而暂无法执行，标记为 `BLOCKED: true`，需在条件就绪后由 QA 重新评估并解除阻塞。

| 阻塞项 | 原因 | BLOCKED 状态 | 零成本替代方案 |
| --- | --- | --- | --- |
| 微信内置浏览器兼容性测试 | 目标市场未定，微信生态优先级尚未确认 | `BLOCKED: true` | Chrome DevTools 内置设备模拟覆盖大部分 UA 行为；本地 Android/iOS 真机抽查微信内置 WebView |
| 移动端真机矩阵（iPhone 13 / SE / Pixel 7 / S22） | 是否采购 BrowserStack 等真机云测服务未定 | `BLOCKED: true` | 浏览器内置设备模拟（Chrome DevTools）+ 本地真机抽查 + Playwright 多视口（375 / 390 / 412 / 768 / 1024） |

**解除阻塞的判定路径**：当目标市场确认后，微信兼容性测试可由真机 + 微信开发者工具降级开展；当 BrowserStack 采购决策落定后，真机矩阵可由云测平台覆盖。在任一项解除前，QA 不对该项出具"已覆盖"结论。
