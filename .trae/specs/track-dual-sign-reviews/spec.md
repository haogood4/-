# 人工复核双签待办清单 Spec

## Why

[政策资讯原文核对 SOP](../policy-source-verification/spec.md) 首轮 AI 辅助核查已完成，6 篇博客修订后均为「有条件通过」，但预部署清单 §12 的 P0 上线准入要求**政策研究员第一签 + 主编/法务第二签**。当前双签事项散落在各核对档案的签字栏中，无统一追踪入口，容易漏签、逾期、无法排序。需要一份结构化、可排序筛选、可追溯的双签待办清单。

## What Changes

- 新增 `docs/policy-verifications/dual-sign-todo.md`：双签待办主清单（Markdown）
  - 主表：ID / 事项 / 对象文件 / 优先级 / 提交时间 / 当前状态 / 第一签责任人 / 第二签责任人 / 复核截止日期 / 关联档案
  - 每项附「复核要点」与「判断标准」明细小节（复核人可逐项打勾）
  - 状态流转规则 + 排序/筛选使用说明（按优先级、提交时间、状态）
- 新增 `docs/policy-verifications/dual-sign-todo.csv`：同一数据的机器可读版（表格软件/脚本可直接排序筛选）
- 修改 `docs/policy-verification-checklist.md`：使用规则追加第 6 条「双签事项统一登记于 dual-sign-todo，状态变更须当日同步」
- 修改 `docs/policy-verifications/2026-09/policy-verification-report.md`：上线决策段追加待办清单链接

## Impact

- Affected specs：policy-source-verification（其产出 6 份档案是本清单的数据源）
- Affected code：仅文档（docs/），无 src 代码、无构建产物变化
- 不新增依赖、不新增页面、不改数据模型

## ADDED Requirements

### Requirement: 双签待办主清单
系统 SHALL 提供 `dual-sign-todo.md`，登记全部待复核事项（首批 7 项：6 篇文章复核 + 1 项批次报告签署），每项含完整字段：

| 字段 | 约束 |
|---|---|
| ID | `DS-YYYYMM-序号`，全局唯一、不可复用 |
| 优先级 | P0（阻塞上线/存在性风险）/ P1（时效强）/ P2（常规） |
| 提交时间 | 进入待办的日期（首批统一 2026-09-19） |
| 当前状态 | 待首签 → 首签通过待二签 → 通过 / 退回重核 / 待二次核对（重写稿），单一状态值 |
| 第一签责任人 | 政策研究员（指定姓名或角色占位） |
| 第二签责任人 | 主编；金融/健康/法律类追加法务 |
| 复核截止日期 | P0=提交后 3 个工作日；P1=5 个工作日；P2=10 个工作日 |
| 关联档案 | 指向对应 `<slug>-verification.md` 链接 |

#### Scenario: 复核人执行双签
- **WHEN** 政策研究员打开某事项，按「复核要点」逐项核对且全部满足「判断标准」
- **THEN** 在档案签字栏与本清单状态列同步更新（首签通过待二签），并记录日期

#### Scenario: 发现不符
- **WHEN** 任一复核要点不满足判断标准
- **THEN** 状态置「退回重核」，问题记入档案 §5 问题清单，重新走全量核对

#### Scenario: 逾期未签
- **WHEN** 当前日期 > 复核截止日期且状态未达「通过」
- **THEN** 该项标 🕐 逾期，对应文章维持「不得上线」，批次风险等级不得降为 🟢

### Requirement: 每项复核要点与判断标准
每个事项 SHALL 附「复核要点」清单（3-6 条，源自核对档案中的高危发现）与对应「判断标准」（可二元判定的表述，如「与新华网 2026-08-20 报道数值一致 = 3.0%/3.5%」），保证不同复核人结论一致。

### Requirement: 排序与筛选
清单 SHALL 支持：
1. Markdown 版：主表默认按优先级排序，附「按状态视图」与「按截止日期视图」两张速查表；文档头给出排序/筛选操作说明
2. CSV 版：列名固定、UTF-8 带表头，可直接在表格软件按任意列排序筛选
3. 状态值枚举统一（禁止自由文本），保证可筛选

### Requirement: 可追溯性
- 已完成事项不删除，状态改为「通过」并保留签署日期（归档可追溯）
- 新增事项只追加新 ID；清单头部维护「变更记录」表（日期/变更内容/操作人）

## MODIFIED Requirements

### Requirement: 核对 SOP 使用规则（policy-verification-checklist.md）
追加第 6 条：
> **双签登记**：所有核对产生的待签/待复核事项统一登记于 `dual-sign-todo.md`（含 CSV 版），状态变更须于当日同步两处；逾期未签的文章不得上线。

## REMOVED Requirements

无。

## 风险

| 风险 | 缓解 |
|---|---|
| 责任人未指定姓名导致无人认领 | 清单允许角色占位，但截止前 3 天须落实到姓名；逾期自动标 🕐 |
| Markdown 与 CSV 双源不一致 | 文档头声明「CSV 为数据源镜像」，状态变更同一提交内更新两处 |
| 清单沦为摆设 | 与预部署 §12 P0 项挂钩：deploy 前人工检查「无 P0/P1 未闭环项」 |
